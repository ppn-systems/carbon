## Executive summary

1. **Namespaces already match folders everywhere** (0 mismatches in 1,246 files, tests included). Every product and test project has `RootNamespace == AssemblyName ==` the project file name. `CodeHygieneTests.Namespaces_ShouldMatchFolderStructure` guards production code only, and still carries an empty allowlist plus a "stale allowlist" test. **Action:** extend the rule to `tests/`, and drop the allowlist so it becomes a plain positive rule (N-1).
2. **Project names do not say which layer they belong to.** The server projects are `Carbon.Abstractions`, `Carbon.Application`, `Carbon.Handlers`, `Carbon.Infrastructure` and `Carbon.Host`, yet the sixth is `Carbon.Server.Configuration`. The engine has `Carbon.Configuration` and contracts has `Carbon.Contracts.Config`. This makes three "config" projects in three layers, and the server's `Carbon.Abstractions` reads as if it were shared by every layer (P-1). It has the highest clarity value, but the rename touches about 230 files. It needs its own PR, at a quiet moment.
3. **Six vague `*Manager`/`*Helper` types** remain (T-1). `EntityManager` is the ECS store (59 references). `SceneManager`/`ISceneManager` and `InputManager`/`IInputManager` are in graphics. The helpers are `CharacterSkillMaskHelper`, `PacketReplyHelper`, `TopographyHelper` and `ScreenshotHelper`, plus a private `CollectionsMarshalHelper` wrapper. Every one of them has a name that says what it is (table below).
4. **The same concept appears under several names.**
   - Auth results: `AuthResult` (packet), `AuthOutcome` (server) and `AuthenticationResult` (desktop).
   - Two unrelated `LevelBand` types.
   - Two unrelated `ScaledMonsterStats` types.
   - Monster and NPC specs in `Carbon.Items/Catalog` (`WorldActorCatalog`), although `Carbon.Creatures` owns monsters (T-3…T-6).
   - The Postgres stores use the abbreviation `Pg*`, while their Sqlite siblings spell out `Sqlite*` (T-2).
5. **85 files hold more than one top-level type**, and 9 of them are named after no type they declare (F-1). Examples: `CvgJsonModels.cs` holds 26 DTOs and `OutboundTickBuffer.cs` holds 22 records. Splitting them is mechanical, so it goes one project per PR.
6. **Data naming is already consistent.**
   - Every JSON property in `resources/` is camelCase. The only non-camel keys are map keys that are ids: `stamina.json → itemSwingCosts`, and the animation names in monster rigs.
   - Every id value is lower_snake: 185 in the catalog, plus 86 in config and 206 in art.
   - Every locale key segment is lower_snake. Every art file stem matches the id it holds.
   - All five engine JSON contexts set `PropertyNamingPolicy = CamelCase`.
   - Only small items remain (D-1…D-3). No config key or i18n key needs a rename for consistency.
7. **The Async suffix and the `I` prefix are almost clean.** Four `WorldCommandQueue.Submit*` methods return `ValueTask` without `Async`. No interface misses the `I` prefix. Boolean properties mostly read as affirmative phrases, which is all the guidelines require. About 70 of them use no `Is`/`Has`/`Can` prefix (B-1). That is optional in the guidelines, so they are listed but not renamed in bulk.
8. **Two folders are dumping grounds:** `Carbon.Desktop.Rendering/Hud` (58 files) and `Carbon.Maps/Building` (30). Crafting, Enhancement and Repair are each split between `Carbon.Items` (definitions) and `Carbon.Economy` (transactions) (S-1…S-3).

## How to read this

- IDs: `N` (namespace/project), `P` (project naming), `T` (type naming), `F` (file layout), `B` (member naming), `S` (folder structure), `D` (data keys and ids).
- **Value** is how much a reader or agent gains: high, med or low. **Blast** is the number of files a rename touches. **Risk** is the chance of a merge conflict with in-flight sessions: combat animation, menu UI, graphics, the race/body model (ADR-042) and the `WorldGameplayScene` split.
- Rank = value first, then smaller blast. The [Phase 2 plan](#phase-2-plan) orders the PRs by that rank.

### T-10 Interfaces, Async, misleading and non-English names

- **Interfaces:** `naming.py iface` → 0. Every interface starts with `I` + PascalCase, and no class looks like one. **Guard PR** locks this in.
- **Async:** `naming.py async` → 4. They are `WorldCommandQueue.Submit` (×2) and `SubmitTargeted` (×2) (`server/Carbon.Application/World/Commands/WorldCommandQueue.cs:114,124,128,132`), and all four return `ValueTask<WorldMutationOutcome>`. Every caller is already an `…Async` method. **Rename** them to `SubmitAsync` / `SubmitTargetedAsync`, and guard that every method returning `Task`/`ValueTask` ends in `Async`, apart from the entry point `Main`.
- **Non-English or non-ASCII identifiers:** none. The only non-ASCII hits are Vietnamese test strings in `TrueTypeFontStackTests.cs:24,70`, and those are data.
- **Misleading names:** T-6 (actors in Items), T-5 (one name, two shapes) and `ServerGameData` (T-1). `Carbon.Contracts.Items` holds non-item packets, listed as S-3.
