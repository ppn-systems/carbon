## How the tool decides

- **Side.** A reference in `server/` is the server. A reference in `desktop/`, `wasm/` or `graphics/` is the client.
  A reference in `contracts/` or `engine/` belongs to the sides whose code calls the enclosing member, followed
  transitively through calls, interface implementations and overrides. So `ChunkDeltaPacketMapper.ToPacket` counts as
  a server write because only the server calls it.
- **Write.** The property is the target of an assignment or object initializer, is passed `ref` or `out`, or has
  `Add`/`Insert` called on it, or an element assigned. Every other reference is a read. Assignments inside
  `ResetForPool`/`Reset`/`Clear`/`Dispose` in `contracts/` are pool resets, not writes. Tests are excluded.
- **Sent by.** The side that rents (`PacketFactory<T>`), creates or fills the packet. A sender is marked
  "only from uncalled …" when no production code reaches the member that sends it. Entry points are handlers,
  `Main`, constructors, and members that override or implement a library member.
- **Handled by.** The server, when a `[PacketOpcode]` handler names the opcode. The client, when it calls
  `On<T>`, `RequestAsync<T>` or `StreamAsync<T>` for it.

Known blind spot: library code that reads a property through an interface. The only such case is
`IPacketStreamable.IsEndOfStream`, which the Nalix SDK reads on the four streamed packets. Those four fields are flagged
"never read" in the generated tables but are live (see W-14).

## Summary

The protocol is in good shape. Every opcode is unique and inside its band. Every C2S packet has a server handler,
and every live S2C packet has a client handler. All string fields are names or keys except one (W-16).

The dead weight is in three places:

1. **Five dead opcodes, and two more that only uncalled code sends** (W-1 … W-4). These are packets superseded by
   later ADRs whose old path was never deleted: the map info pair replaced by `CharacterEnterWorld`, the single-item
   trades replaced by the D18 basket, and the generic vendor replaced by village traders. Each keeps a live server
   handler, and so a live attack surface, for a request no client sends.
2. **About 15 fields that the receiver never reads** (W-5 … W-12). Most were carried over from an earlier design
   (dirty masks, repair quotes, swim state). Some are derivable on the receiver.
3. **A group of fields that an Accepted ADR says the client uses, but the client does not** (W-17 … W-20). These are
   unfinished features, not dead fields. They need a decision, not a deletion.

### Gaps and band notes

- No duplicate opcodes. `ProtocolContractGuardTests` already fails the build on a duplicate value or a value outside
  its module band.
- Missing: a rule that every opcode has both a sender and a handler. That missing rule is why W-1 … W-4 survived
  their ADRs. Phase 2 adds it as a positive rule (see [Plan](#plan)).
- The comment bands in `ItemOpCode.cs` overlap: "Repair 0x4050–0x4057" and "Trader basket 0x4052–0x4057" claim the
  same range, and "S2C push 0x4030–0x40FF" covers the whole tail of the band. The values do not collide, but the comments
  no longer guide where a new opcode goes. Constants are also not in numeric order (`0x4058` sits after `0x4079`). Low
  value, cosmetic: fix when the file is next touched.
- The intentional gap at `0x4009` is documented in place. Every other gap is unallocated space.

### Widths

The tool lists every field's type. None warrants narrowing:

- **Hot path.** `EntityDeltaBatch` and `EntitySpawn` already use `ushort` for ids and `byte` for levels.
  `EntitySpawn.LootCount` is `int` because gold piles exceed `ushort`.
- **Signed sentinels.** `DropInventoryItem.Quantity` and `DestroyInventoryItem.Quantity` are signed on purpose, since
  `<= 0` means "the whole slot". Narrowing them changes behaviour.
- **Cold paths.** The remaining wide fields (`InventorySlotItem.Count`, `TraderStock.SecondsUntilRestock`, prices) sit
  on cold paths. Narrowing them saves a few bytes per window open, which is not worth a protocol bump.

### Enums and types

- **Unreferenced enum values.** `CharacterTraits.TutorialCompleted`, `PvpEnabled` and `ForgeUnlocked` are reserved
  flag bits that nothing sets or tests. They cost nothing on the wire (one `ulong` bitmask). Keep them as reserved bits
  or document them as reserved. `OpStatus.EnhancementFailed` is never returned by production code, only by test
  helpers. The forge reports failure through `EnhancementResult.Outcome`. Low value.
- **Named mask bits.** `CharacterSkillMask.Whirlwind/ArcaneNova/VitalSurge` are not referenced by name, but are used
  numerically through `CharacterSkillMaskHelper.BitForSkill`. Live.
- **Contract types with no production reference.** `MapTileTraits` is used by engine only, as tile flags inside
  `MapChunkDelta.TileTraits`, so it is live. Apart from W-1 … W-4, no other contract type is unreferenced. There are no
  standalone DTOs: every `[SerializePackable]` type is a packet.

## Plan

Each batch is one PR, branched from `origin/master` and independently mergeable. Each removes both sides together,
bumps `CarbonProtocol.Version` once, and ships round-trip tests plus a mutation table.

1. **ADR-038 and the guard.** ADR-038 (Accepted) defines what counts as dead (class A above) and the version-bump
   policy. A contract test asserts that every opcode constant has a sender and a handler, written as a positive rule.
   An exception needs an attribute with a reason in code. There is no allowlist.
2. **Dead opcodes:** W-1, W-2, W-3, W-4.
3. **Dead fields:** W-6 … W-12.
4. **`DirtyMasks`:** W-5, alone, because it touches the hot path.
5. **After ADR-037 lands:** W-13.

B items (W-17 … W-20) are not removed. They are listed for the owner to decide.
